## Component Overview

**Category:** UI Rendering / Page Section  
**Primary Use:** Display the Contact Us section consisting of a form area and static contact information (address, email, helpline, office hours).

This component is intended to be **used directly inside pages** and can be reused wherever a contact section is required. It is a **UI-only component** and does not handle data fetching or submission logic.

---

## Responsibility Contract

### What this component does

- Renders a left section containing helper text and the `Hero` form component
- Renders a right section displaying office contact details
- Displays fallback static values when contact data is not provided
- Handles responsive layout and styling

### What this component does NOT do

- Does not submit form data
- Does not fetch contact details
- Does not validate form input
- Does not manage business logic or API calls

> This is a **pure UI composition component**.  
> All data fetching, validation, and side effects must be handled by the parent.

---

## Component Contract (Props)

### Props

| Prop             | Type  | Required | Description                                            |
| ---------------- | ----- | -------- | ------------------------------------------------------ |
| `contactDetails` | `any` | No       | Object containing contact information used for display |

### Expected Shape (Reference)

```ts
contactDetails: {
  contactDetails?: {
    address?: string;
    email?: string;
    helpline?: string;
    officeHours?: string;
  };
}
```

If any field is missing, a default fallback value is rendered.

---

## Visual Structure

### Layout

- **Left Section**

  - Informational text
  - `Hero` component (form UI)

- **Right Section**

  - Office address
  - Email
  - Helpline number
  - Office hours

The layout switches between stacked and side-by-side based on screen size.

## Styling & Customization

- Uses Tailwind utility classes for spacing, typography, and layout
- Gradient background and bordered container for contact details
- Responsive behavior handled via breakpoint-specific classes

### Customization Guidelines

- Modify spacing and typography classes for design changes
- Keep layout structure intact to preserve responsiveness
- For different layouts, wrap this component instead of modifying internals

---

## Modification Guidelines

### Safe to modify

- Text copy
- Tailwind utility classes
- Fallback values
- Container spacing and alignment

### Do NOT modify

- Prop access pattern without updating documentation
- Structural layout unless required globally
- Responsibility boundary (no business logic inside)

---

## Dependencies & Assumptions

- Depends on a local `Hero` component for the form UI
- Assumes contact data is already prepared by the parent
- No external providers or context required

---

## When to Use / When NOT to Use

### Use when

- Rendering a Contact Us page or section
- Displaying static or CMS-driven contact information
- Embedding a contact form alongside office details

### Do NOT use when

- Handling form submission logic
- Managing API requests
- Applying conditional business rules

---

## Summary

`ContactUsForm` is a **UI composition component** that combines a form section and contact information into a single responsive layout.
It is designed for reuse, safe copy-paste, and clear separation from business logic.
